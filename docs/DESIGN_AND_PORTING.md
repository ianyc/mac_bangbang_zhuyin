## 1. 專案概要

- **目標**：操作方式比照 Windows 微軟新注音（使用者習慣的舊版行為），而且**選字要準**。
- **使用者**：自用為主，台灣使用者，標準大千鍵盤排列。不上架；以後可能分享給朋友，所以資料來源只用授權清楚的。
- **版本**：macOS 版 0.3.0（git commit `4e773d2`）。還原點標籤 `v0.2.1`。
- **語言與技術**：Swift、Swift Package Manager、macOS InputMethodKit。選字引擎不依賴任何 UI 框架，可以單獨測試。
- **規模**：Swift 原始碼約 2,600 行，37 個單元測試。

## 2. 起點：使用者的需求與痛點

使用者覺得 macOS 內建注音難用，想要像 Windows 微軟新注音一樣好用。他明確指出的痛點：

1. 注音模式下 **Shift + 字母輸出全形英文** → 要輸出**半形**英文。
2. 選字時要把游標移到字的**後面** → 要像微軟，游標在字的**前面**就能選。
3. 組字中、沒有待拼注音時按空白，會跳出最後一個字的候選 → 要輸出空白。
4. 用 Caps Lock 切換中英時，快速按偶爾切不過去（推測是系統層問題）。

他在 Windows 上也遇到**新版微軟注音「變笨」**：打「越更新越難用」會被選成「月更新越南用」。所以**基本的預測選字要正確**，是這個專案最重要的要求。這也是使用者想在 Windows 上做一套的原因。

## 3. 行為規格（最終版 0.3.0）

> 這一節是要在 Windows 上重現的行為。引擎行為的可執行規格在 `Tests/BangbangEngineTests/BangbangEngineTests.swift`，建議原樣移植成 Windows 端的測試。

### 3.1 名詞

- **注音拼字區（composer）**：正在拼、還沒按聲調的那一個音節，例如「ㄇㄚ」。
- **組字區（composition）**：已經打好、還沒送出的一串內容，以底線顯示在游標處。每一格（token）是一個注音音節，或是一個直接輸入的字元（英文、標點、空白）。
- **候選窗**：按 ↓ 叫出的直式清單。
- **送出（commit）**：把文字真正輸入到應用程式。

### 3.2 拼注音（標準大千）

| 鍵 | 注音 |
|---|---|
| `1 q a z 2 w s x e d c r f v 5 t g b y h n` | ㄅ ㄆ ㄇ ㄈ ㄉ ㄊ ㄋ ㄌ ㄍ ㄎ ㄏ ㄐ ㄑ ㄒ ㄓ ㄔ ㄕ ㄖ ㄗ ㄘ ㄙ |
| `u j m` | ㄧ ㄨ ㄩ |
| `8 i k , 9 o l . 0 p ; / -` | ㄚ ㄛ ㄜ ㄝ ㄞ ㄟ ㄠ ㄡ ㄢ ㄣ ㄤ ㄥ ㄦ |
| 空白 `6 3 4 7` | 一聲 ˊ ˇ ˋ ˙ |

- **依實體按鍵位置對應**（美式鍵盤），不受 Caps Lock 與鍵盤配置影響。
- 一個音節有三個位置：聲母、介音、韻母。**同一個位置再按一次會取代**，例如 ㄅㄚ 再按 ㄇ 變成 ㄇㄚ。
- **Backspace**：拼字區有注音時，刪掉**最後輸入**的那個符號。
- **聲調鍵完成音節**：拼字區是空的時候按聲調鍵，什麼都不做。組字中按會嗶一聲；沒有組字時則靜靜吃掉，不輸出數字。
- **音節不存在於詞庫時拒絕**：嗶一聲，拼字區保留，讓使用者修改。但有一個例外：ㄐㄑㄒ 後面打成 ㄨ 時，自動改成 ㄩ 再試一次。
- **組字中按空白**：拼字區有注音時是一聲，沒有注音時見 3.3。

### 3.3 組字區

- **整句選字**：每完成一個音節，就對**整個組字區**重新選出最合理的斷詞與用字。後面打的字可以改變前面的選擇，例如打到第二個 ㄩㄝˋ 時，前面的「月」會變成「越」。
- **游標**：← → 移動一格，Home／End 移到最前／最後。新的音節插入在游標處。拼字區有注音時按方向鍵會嗶一聲。
- **Enter**：送出整個組字區，拼字區裡沒拼完的注音直接丟掉。
- **空白（沒有待拼注音時）**：在組字區**加一個半形空白**，**不送出**，按 Enter 才一起送出。這是使用者實測後的要求，原本「送出並加空白」的設計已經被改掉。
- **Backspace**：沒有拼字中的注音時，刪除游標前一格。已在最前面時嗶一聲。
- **Delete（向前刪除）**：刪除游標後一格。
- **Esc**：拼字區有注音時清掉拼字區；沒有時**清掉整個組字區**。
- **長度上限 20 格**：超過時把最前面的詞自動送出。
- **一格一字**：每個詞的字數等於它佔的格數。顯示文字、游標位置都靠這個假設計算。
- **組字中按到沒有對應的鍵**：吃掉不處理，以免干擾。↑、Tab、PageUp、PageDown 在組字中也一律吃掉。
- **沒有組字時**，上述按鍵全部交還給應用程式。

### 3.4 候選字（↓）

- **游標在某個字的前面**：列出**從這個字開始**的所有詞，長詞在前、單字在後。例如游標在「輸」前面，會列出「輸入法、輸入、輸、書、舒…」。
- **游標在最後面**：**只列出最後一個字**的單字候選，不列出結束在最後的長詞。例如打「中文輸入法」後按 ↓，只會出現「法、髮…」。
- **排序**：同長度依上下文分數排序，也就是前一個詞接這個詞的機率加上選字記憶的加分。
- **目前顯示的字詞一律排第一筆**，預設反白。如果它是某個長詞的一部分，就把目前顯示的那個字排第一。這是比照微軟新注音。
- **候選窗操作**：

| 鍵 | 行為 |
|---|---|
| 1–9 | 選本頁對應的候選 |
| ↑ ↓ | 移動反白 |
| Enter | 選反白的候選 |
| 空白、→、PageDown | 下一頁（最後一頁再按回到第一頁） |
| ←、PageUp | 上一頁（第一頁再按跳到最後一頁） |
| Esc、Backspace | 關閉候選窗 |
| 其他鍵 | 關閉候選窗，再把這個鍵當一般按鍵處理 |

- **選完之後游標移到該詞後面**，方便繼續往後修正。原本游標就在最後的話則不動。
- **手動選字後，選字位置前面的字全部固定不變**：前面的詞會被「釘住」，跨越選字位置的詞會拆成單字釘住。後面的字仍可依新的上下文重新選。這是使用者實測後的要求，例如把「中文」的「文」改成「聞」，「中」不能變。
- 每頁 9 個，直式排列，有頁碼（例如 1/5）。

### 3.5 英文、標點與數字

- **Shift + 字母** → 半形**大寫**字母。
- 標點對應，仿微軟新注音與小麥注音的標準大千配置：

| 按鍵 | 輸出 | 按鍵 | 輸出 |
|---|---|---|---|
| Shift + , | ， | ' | 、 |
| Shift + . | 。 | [ ] | 「 」 |
| Shift + / | ？ | Shift + [ ] | 『 』 |
| Shift + ; | ： | Shift + ' | ； |
| Shift + 1 | ！ | Shift + 9 / 0 | （ ） |
| Shift + 2–8 | @ # $ % ^ & *（半形） | Shift + - / = | _ +（半形） |
| ` | ` | Shift + ` | ～ |
| = | = | \ / Shift + \ | \ \|（半形） |

- **全形標點不論何時都進入組字區**，按 Enter 才送出，比照微軟新注音。所以在沒有任何字時直接打「，」，也會先進入組字區。
- **半形英數符號**（例如 Shift+字母、@、數字鍵盤）：沒有組字時直接送出；組字中則插入組字區。
- **數字鍵盤**輸出半形數字與運算符號，規則同上。
- 標點、英文、空白在選字時都視為**句子邊界**：它前後的字詞選擇互不影響。

### 3.6 符號候選與括號配對

- **在符號上按 ↓**：列出它的全形／半形，以及同一個鍵上的另一個符號，目前的符號排第一。分組見 `InputSession.swift` 的 `Punctuation.groups`：

```
，, ＜ < 〈 《        。. ． ＞ > 〉 》        ？? ／ /        ：: ； ;
、' ； ＂ " “ ” ‘ ’   ！! １ 1   @＠２2   #＃３3   $＄４4   %％５5   ^＾︿６6
&＆７7   *＊８8   （(９9   ）)０0   _＿-－—   +＋=＝
「『[{［｛【〔   」』]}］｝】〕   ～~`‵   \＼|｜   半形空白 全形空白
```

- 候選窗裡的空白顯示為「半形空白」「全形空白」。
- **括號自動配對**：在組字區把括號換成另一種括號時，配對的另一半一起換。例如把「『』」的前半換成「「」，後半自動變成「」」；改後半也會帶動前半。
  - **依層數配對**：例如「『A『B』C』」改最外層的前半，只會改到最後一個「』」。
  - 換成不是括號的符號（例如「（」換成「9」）時，另一半不動。
  - 配對表：「」『』（）〈〉《》【】〔〕［］｛｝“”‘’ 以及半形 () [] {}。
  - 只對還在組字區裡的括號有效。

### 3.7 選字記憶

- **只在使用者用 ↓ 手動選字時學習**。選符號不學習；自動選中、刪掉重打都不算。
- **上下文記憶**：「前一個詞相同、讀音相同」算同一格。句首或標點後的前一個詞是「句子邊界」。
  - 格內**選最多次的字詞一定是預設**，不管它是不是常用字。
  - **次數一樣時，以最近一次選的為準**。
  - **每個字詞最多累計 3 次**，舊習慣最多改選 3 次就能換過來。
  - 例子：在「我愛」後面選「妳」1 次，下次預設「妳」；再改選「你」1 次，平手、最近是「你」，所以預設「你」。
- **單詞記憶**：只看讀音的一格，勝出者在任何位置都小幅加分。
- **選錯了不用刪除，改回來就好**。沒有「刪除單筆記憶」或「清除全部」的功能，見第 6 節。
- **儲存位置**：macOS 是 `~/Library/Application Support/BangbangZhuyin/user-model.json`，格式見 4.7。

### 3.8 其他按鍵與系統整合（macOS 版的做法）

- **Command／Control／Option 組合鍵**一律交給應用程式，不動組字區。
- **中英切換**：沿用 macOS 系統的「Caps Lock 切換 ABC」，輸入法本身不處理。如果 Caps Lock 真的鎖定成大寫，就先送出組字區，按鍵交給應用程式。Windows 沒有這個系統功能，見 8.5。
- **切換應用程式或輸入法時**，送出整個組字區。
- **組字區的顯示**：整段單底線，候選窗開啟時正在選的那段改為粗底線，游標位置正確。
- **候選窗位置**：放在游標那一行下方，放不下就放上方，水平方向不超出螢幕。不搶走焦點，支援深色模式，字型用 PingFang TC 20pt。
- **輸入法選單**只顯示版本號。

## 4. 選字引擎設計

### 4.1 兩種資料：詞庫與語料

| | 詞庫 | 語料 |
|---|---|---|
| 是什麼 | 一本字典：有哪些詞、每個詞怎麼念 | 大量真實文章 |
| 決定什麼 | **打不打得出來** | **選哪一個** |
| 來源 | 小麥注音 McBopomofo（MIT），約 16 萬詞與讀音 | PTT、中文維基、行政院即時新聞，約 2.2 億詞 |

**詞庫**（`data/mcbopomofo/`，快照版本見 `SOURCE.txt`）：
- `BPMFBase.txt`：單字讀音，最後一欄是字集，例如 big5、utf8。
- `BPMFMappings.txt`：詞的讀音。
- `phrase.occ`：小麥注音的詞頻。
- `heterophony1/2/3.list`：破音字的讀音順位。
- `exclusion.txt`：詞頻扣除規則，例如「國一下」裡的「一下」不算進「一下」的次數。

棒棒注音對詞庫做了這些修正：
1. **補上打字時的讀音**，函式是 `typedVariant`。詞庫常記變調或書面讀音，但大家打本調，所以為詞補一個變體讀音：
   - 「不」：ㄅㄨˊ → ㄅㄨˋ（不要）
   - 「一」：ㄧˊ／ㄧˋ → ㄧ（一下）
   - 「得」不在詞首時：ㄉㄜˊ → ㄉㄜ˙（我覺得）

   只對「每個破音字都用常見讀音」的詞補，避免「說得 ㄕㄨㄟˋ」這種罕見讀法被補上。
2. **常用破音字單獨成字時的讀音比例**（`data/reading-weights.txt`）：例如「得」ㄉㄜ˙ 0.55、ㄉㄜˊ 0.4、ㄉㄟˇ 0.05。表裡沒列的讀音視為罕用。
3. **非 Big5 字與少用異體字降權**：簡體字、罕用異體字，以及 `data/discouraged-chars.txt` 列出的字（例如「着」），權重乘以 0.01。仍查得到，但不會被自動選中。

**語料**（只用來統計，不會打包進輸入法）：

| 來源 | 授權 | 用量 |
|---|---|---|
| PTT 文章（Hugging Face `yuhuanstudio/PTT-pretrain-zhtw`） | Apache-2.0 | 約 50 萬篇，口語 |
| 中文維基（`yuhuanstudio/wikipedia-zh-tw`，2023_05 版） | CC BY-SA 4.0 | 44 份中的 4 份，約 23 萬篇 |
| 行政院即時新聞（政府開放資料 opendata/154） | 政府資料開放授權條款 | 約 500 篇，偶數篇訓練、奇數篇測試 |

> **語料授權原則**：使用者明確決定**只用授權清楚的語料**。授權不明的新聞合集（例如 `liswei/news-collection-zhtw`，59 萬篇）已被否決。

### 4.2 建模型流程（`bangbang-tool build-lm`）

1. **讀詞庫**，建立詞表。0 號詞是句子邊界 `<s>`。
2. **讀語料**：每篇是 JSON 裡的一個 `"text"` 字串。PTT 文章去掉「內文: 」之前的檔頭；每 100 篇保留 1 篇不訓練，作為評測。
3. **切段**：遇到詞庫外的字元（標點、英數、空白）就切開。緊接在數字或英文後面的段落（略過空白）**不算句子開頭**，不統計「句首→第一個詞」。這是為了避免「8月31日」「3 月 2 日」讓「月」看起來很常出現在句首；原本這個問題正是「越更新越難用」選錯的元兇。
4. **斷詞**：以小麥注音詞頻做最大機率斷詞（字典樹＋動態規劃）。
5. **統計**：單詞次數、雙連詞次數 c(v,w)、隔一個詞的詞對次數 c(u,_,w)。
6. **估計機率**：
   - 單詞機率：P(w) = 0.8 × 語料頻率 + 0.2 × 小麥詞頻（加 0.5 平滑）。
   - 雙連詞用**插值絕對折扣**：P(w|v) = max(c(v,w) − D, 0) / c(v) + λ(v)·P(w)，其中 λ(v) = D·N₁₊(v)/c(v)，D = n₁/(n₁ + 2n₂)，約 0.621。
   - 只存次數 ≥ 2 的雙連詞，約 978 萬組；其餘在執行時用 λ(v)·P(w) 退回估計。
   - **隔詞搭配**：只收次數 ≥ 8 且 PMI ≥ ln 20 的詞對，加分 = min(4, 0.5 × PMI)，約 53 萬組。用來處理「越 ＿ 越」這類前後呼應的句型。
   - **讀音權重** log P(讀音|詞)：詞一律為 0；單字依讀音比例表或破音字順位（1、0.5、0.25）。罕用讀音 = min(0.05, 10⁻⁶ / P(w))，這是絕對上限，避免「的(ㄉㄧˊ)」蓋過「敵」。
7. **寫出模型檔** `build/bangbang-v3.lm`，約 90 MB，格式見 4.8。

建模型在一般 Mac 的 CPU 上約 50 秒、最多用 2.5 GB 記憶體。這是傳統統計語言模型，不是神經網路，不需要 GPU。

### 4.3 執行時的打分

每個候選節點（詞 w、前一個詞 v、前前一個詞 u）的分數，全部是自然對數：

```
score = logP(w | v)              ← 有存雙連詞就查表，否則 logBackoff[v] + logUnigram[w]
      + readingWeight(w, 讀音)
      + skip(u, w)               ← 隔詞搭配加分，u 是句子邊界時為 0
      + userBonus(v, w, 讀音)    ← 選字記憶，見 4.7
```

標點、英文、空白這類直接輸入的字元不計分，而且會把上下文重設為句子邊界：它後面的詞，v 與 u 都視為 `<s>`。

### 4.4 整句搜尋（`Decoder.decode`）

1. **建格子（lattice）**：從每個位置 i 開始，往後延伸 1 到最長詞長個音節，查讀音表。
   - 單字只取分數最高的前 40 個，詞只取前 12 個；讀音表內的候選已依「單詞機率 + 讀音權重」排好。
   - 查到「沒有以這串音節開頭的更長讀音」就停止延伸。
   - **釘選（pin）**：使用者手動選的詞、被固定的前文，只允許「剛好是那個詞」的節點，與它重疊的其他節點都排除。釘選的詞就算不在前 40 名也會加入。
2. **二階搜尋**：狀態是「走到某節點、而且前一個詞是 v」，每個節點保留分數最高的 6 種前一個詞。這樣就能同時算雙連詞與隔詞搭配。
3. 取結束在最後的最佳狀態，回溯得到斷詞與用字。

速度：評測 8000 句只要 1.3 秒，平均每句約 0.2 毫秒，所以每次按鍵都重算整句也很輕鬆。

### 4.5 候選清單（`Decoder.candidates`）

- 範圍依 3.4 決定：游標在字前面時，是從游標開始的各種長度；游標在最後時，只有最後一個字。
- 同一長度內，依「logP(候選 | 前一個詞) + 讀音權重 + 記憶加分」排序。前一個詞是選字結果中剛好結束在該位置的詞，沒有的話用句子邊界。
- 該位置是符號時，改列符號候選（見 3.6）。
- 「目前選字排第一」在 `InputSession.openCandidates` 處理。

### 4.6 組字區操作（`Composition`）

- **插入**：插入點落在某個釘選詞中間時，該釘選失效；後面的釘選位置往後移。
- **刪除**：刪掉的格子所在的釘選失效；後面的釘選往前移。
- **選字（select）**：
  1. 先把選字位置前面目前顯示的字全部釘住（`freezeText`）。
  2. 移除與新選字重疊的舊釘選。
  3. 釘上新選字，重新計算整句。

  選的是符號時，直接換掉該格，並處理括號配對。
- **送出開頭（commitLeading）**：超過 20 格時，送出最前面的詞，並調整游標與釘選。

### 4.7 選字記憶的演算法（`UserModel`）

- **上下文記憶**：以（前一個詞 ID、讀音）為一格，記錄每個詞的（次數，最後時間），次數上限 3。
  - 格內勝出者 = 次數最多者；同次數則最後時間較晚者。
  - **只有勝出者加分**，加分 = max(0, 這格語言模型首選的分數 − 勝出者的分數) + 4。也就是剛好贏過語言模型首選再多 4 分。這個值依格子快取，記憶變動時清空。
- **單詞記憶**：以讀音為一格，同樣的勝出規則，勝出者每次選擇加 0.8 分，最多 3 次。
- **檔案格式**（JSON，第 2 版）：

```json
{
  "version": 2,
  "contextual": { "前一個詞\t詞\t讀音": { "count": 2, "lastUsed": 1763100000.0 } },
  "unigram":    { "詞\t讀音":           { "count": 2, "lastUsed": 1763100000.0 } }
}
```

  - 讀音是音節之間用空白分隔的注音，一聲不加符號，例如 `ㄋㄧˇ`、`ㄍㄥ ㄒㄧㄣ`。
  - 句子邊界寫成 `<s>`。
  - 以文字而不是 ID 儲存，所以重建模型後仍可用。
  - 舊格式（沒有 version、上下文鍵只有兩段）在載入時，會用單詞記錄補回讀音並轉換。
  - 改名前 0.1 版的舊位置會自動複製過來。
- **已知限制**：只記「前一個詞」，沒有記「後一個字」。所以人名中間的字改過之後，後面的字可能把它拉回去，見 7.1。

### 4.8 模型檔格式（第 3 版）

> 這個格式是**跨平台的**：小端序、固定寬度、每個表格都對齊 8 bytes。Windows 可以直接用 `CreateFileMapping`／`MapViewOfFile` 對應後當陣列讀取，**同一個檔案可以直接沿用**。

- **檔頭**：10 個 UInt32。

```
magic = 0x4D4C4242（檔案前 4 bytes 為 "BBLM"）, version = 3,
wordCount V, bigramCount B, keyCount K, codeCount C, entryCount E, skipCount S,
blobBytes, maxPhraseLength
```

- **表格**依序排列，每個表格開頭都補零對齊到 8 bytes：

| # | 表格 | 型別 × 數量 | 說明 |
|---|---|---|---|
| 1 | wordOffsets | UInt32 × (V+1) | 第 i 個詞的 UTF-8 文字在 blob 的 [off[i], off[i+1]) |
| 2 | blob | UInt8 × blobBytes | 所有詞的 UTF-8 文字 |
| 3 | logUnigram | Float32 × V | log P(w)；`<s>` 為 −30 |
| 4 | logBackoff | Float32 × V | log λ(v) |
| 5 | bigramStart | UInt32 × (V+1) | 前一個詞 v 的雙連詞範圍 |
| 6 | bigramNext | UInt32 × B | 範圍內依詞 ID 排序，二分搜尋 |
| 7 | bigramLogProb | Float32 × B | log P(w\|v) |
| 8 | keyCodeStart | UInt32 × (K+1) | 第 k 個讀音的音節範圍 |
| 9 | keyCodes | UInt16 × C | 音節代碼 |
| 10 | entryStart | UInt32 × (K+1) | 第 k 個讀音的候選詞範圍 |
| 11 | entryWord | UInt32 × E | 候選詞 ID，已依「單詞機率 + 讀音權重」由高到低排序 |
| 12 | entryWeight | Float32 × E | 讀音權重 log P(讀音\|詞) |
| 13 | skipStart | UInt32 × (V+1) | 前前一個詞 u 的隔詞搭配範圍 |
| 14 | skipNext | UInt32 × S | 範圍內依詞 ID 排序 |
| 15 | skipValues | Float32 × S | 加分 |

- **讀音（keys）的排序**：依音節代碼序列的字典順序（短的是長的前綴時排在前面），所以可以二分搜尋，也能判斷「有沒有以某串音節開頭的更長讀音」。
- **音節代碼**（UInt16）：`聲母 << 9 | 介音 << 7 | 韻母 << 3 | 聲調`。
  - 聲母 1–21：ㄅㄆㄇㄈㄉㄊㄋㄌㄍㄎㄏㄐㄑㄒㄓㄔㄕㄖㄗㄘㄙ
  - 介音 1–3：ㄧㄨㄩ
  - 韻母 1–13：ㄚㄛㄜㄝㄞㄟㄠㄡㄢㄣㄤㄥㄦ
  - 聲調 1–5：一聲、ˊ、ˇ、ˋ、˙
  - 0 表示該位置沒有符號。
- 舊的第 2 版格式（0.2.1 用的 `build/bangbang.lm`）是整份讀進記憶體的版本，已不使用。

### 4.9 記憶體與效能

- 0.2.1 以前：模型整份複製進記憶體，另外建雜湊表，佔 **141 MB**。
- 0.3.0：mmap 直接對應、不複製，全部改用二分搜尋，隔詞搭配也依前前詞分段。程式本身只佔 **12–13 MB**，選字反而**快一倍**，正確率不變。
- 讀音查詢不複製候選清單，而是回傳指向模型資料的視圖；選字記憶的「文字→ID」索引只在載入時建立。

## 5. 正確率與評測方法

### 5.1 三組測試

| 測試 | 只用小麥詞頻 | 棒棒注音 0.3.0 |
|---|---|---|
| 日常用語 156 句（`Tests/eval/sentences.txt`），整句全對 | 80.1% | **99.4%** |
| PTT／維基中未參與訓練的 8000 句，整句／逐字 | 62.9%／93.5% | **82.8%／97.3%** |
| 行政院新聞中未參與訓練的 8000 句，整句／逐字 | 57.9%／93.2% | **82.1%／97.3%** |

- **日常用語測試**：一行一句，必須整句選對才算通過。需要時用「句子 | 注音」指定讀音，例如 `越更新越難用 | ㄩㄝˋ ㄍㄥ ㄒㄧㄣ ㄩㄝˋ ㄋㄢˊ ㄩㄥˋ`。唯一還錯的是「慢慢地」被選成「慢慢的」（口語兩種都常見）。
- **保留句**：建模型時每 100 篇留 1 篇不訓練，取 4–30 字、不接在數字或英文後面的段落。
- **中文轉注音**：以詞庫斷詞後，每個詞取各字讀音權重總和最高的讀音；同分時依音節排序取第一個，讓結果可以重現。
- **評分**：「他／她／它／牠」與「台／臺」視為相同。

### 5.2 實驗結論（決定參數的依據）

- 加入**雙連詞**：日常 80.1% → 96.2%，保留句 62.3% → 82.3%。
- 修正「**數字後面不算句首**」：「越更新越難用」從錯變對。
- 加入**隔詞搭配**：日常 98.1% → 99.4%，保留句約 +0.6%。
- **雙連詞門檻**：次數 ≥ 3 時模型 65 MB，正確率 −0.7%；≥ 4 時 52 MB，−1.2%。決定維持 ≥ 2。
- 加入**行政院新聞**、**「着」降權**：新聞 70.4% → 75.9% → 82.0%，其他兩組不變。

### 5.3 除錯工具（`bangbang-tool`）

```
convert --lm M ㄩㄝˋ ㄍㄥ ㄒㄧㄣ …        注音轉中文（顯示斷詞）
lookup  --lm M ㄉㄜ˙                     某讀音的候選字與分數
score   --lm M 越 更新 越 難 用           某種斷詞的分數明細
eval    --lm M <測試檔> [--limit N]       算正確率
keys    --lm M [--memory 記憶檔] "5j/ jp6<down><pick:聞><enter>"
                                         模擬按鍵（大千鍵位）。特殊鍵：<space> <enter> <esc> <bs> <del>
                                         <left> <right> <up> <down> <home> <end>，
                                         <pick:字> 在候選窗選指定字，大寫字母 = Shift+字母
```

**建議在 Windows 端也做一個同樣的按鍵模擬器**，用來驗證行為與 Mac 版一致。

## 7. 已知限制與經驗教訓

### 7.1 人名的選字記憶

把「蕭逸群」的「逸」改成「奕」之後，再打「ㄒㄧㄠ ㄧˋ ㄑㄩㄣˊ」仍會出現「逸」，只打「蕭奕」則正確。原因如下：

- 記憶只記「蕭→奕」，但語料裡「逸群」很常一起出現，「奕群」幾乎沒有。
- 後一個字的扣分大於記憶加分：「蕭逸群」−11.3 分，「蕭奕群」−14.5 分。

討論過的解法（**暫緩**）：

- **自動學詞**：改字時，把改的字與前後緊鄰的單字（共三字）記成一個詞，在同樣三個注音時優先。
- 記憶分三層，越具體越優先：三字詞 ＞ 單字搭前一個字 ＞ 單字偏好；每層內都照「最多次優先、平手看最近」。

### 7.2 Caps Lock 快按偶爾切不過去

可能原因有兩個，可能同時存在：

1. 系統切換輸入法需要時間。
2. 蘋果鍵盤的 Caps Lock 有防誤觸延遲。

macOS 版沒有處理。Windows 版的做法見 8.5。

### 7.3 macOS 特有的經驗

- **不要同時啟動兩份輸入法**：已安裝時又手動執行輸入法程式，兩份會搶同一個 IMK 連線名稱，系統那份就失效，必須登出才能恢復。Windows 的 TSF 是 DLL 載入到各應用程式，不會有這個問題，但同樣要避免安裝兩份。
- **兩種安裝位置只能擇一**：`~/Library/Input Methods` 與 `/Library/Input Methods` 同時存在會衝突。
- `hdiutil` 自動估算映像大小時偶爾太小，要明確指定 `-size`。
- 本機簽章、未公證的程式，在其他 Mac 上要用 `xattr -dr com.apple.quarantine` 解除隔離。

## 8. Windows 移植指南

> 以下是建議，Windows 平台細節請以 Microsoft 官方文件為準。

### 8.1 可以直接沿用的東西

| 項目 | 怎麼沿用 |
|---|---|
| **模型檔** `bangbang-v3.lm` | 格式跨平台（4.8），直接 mmap 讀取。檔案約 90 MB、不在 git 裡，可以從 Mac 複製，或在 Windows 重建（8.7） |
| **選字記憶** `user-model.json` | 格式相同（4.7），可以從 Mac 複製過去延續記憶 |
| **詞庫與資料** `data/` | 原樣使用 |
| **測試** | 37 個單元測試是行為規格，請逐一移植；`Tests/eval/sentences.txt` 與評測方法用來確認正確率一致 |
| **引擎邏輯** `Sources/BangbangEngine/` | 約 1,440 行，純邏輯，逐檔移植即可 |

### 8.2 建議架構

Windows 的輸入法是 **TSF（Text Services Framework）的 Text Input Processor（TIP）**，以 **COM 的 in-process DLL** 形式載入到每個應用程式裡。建議：

- **外殼**用 C++ 寫 TSF TIP，取代 `Sources/BangbangZhuyin/`。
- **引擎**移植成 C++（或其他能編成原生 DLL 的語言），對應 `BangbangEngine` 的六個檔案。保留同樣的類別切分：Syllable／Composer、LanguageModel、Decoder、Composition、InputSession、UserModel。這樣行為最容易對齊。
- **引擎與外殼分離**：InputSession 輸入 KeyEvent、輸出（是否處理、要送出的文字、是否嗶聲），外殼只負責和系統溝通。這個介面設計已在 Mac 版驗證過。

可參考的開源專案，請自行確認授權與現況：
- **Microsoft 的 Windows-classic-samples 裡的 IME 範例**（SampleIME）：TSF 輸入法的完整骨架。
- **PIME**（EasyIME/PIME）：台灣開發者的 Windows 輸入法框架。
- **新酷音（libchewing）的 Windows 版**：注音輸入法的 TSF 實作。

### 8.3 TSF 要點（對應 Mac 版的功能）

| Mac 版（InputMethodKit） | Windows（TSF）的對應 |
|---|---|
| `handle(event)` 回傳是否處理 | `ITfKeyEventSink` 的 `OnTestKeyDown`／`OnKeyDown`（決定是否吃掉按鍵）、`OnPreservedKey` |
| `setMarkedText`（底線組字） | 在 edit session（`ITfEditSession`）裡用 composition（`ITfContextComposition::StartComposition`）設定文字與游標；底線樣式用 `ITfDisplayAttributeProvider` |
| `insertText`（送出） | 在 edit session 裡把組字文字定案並 `EndComposition` |
| `attributes(forCharacterIndex:)`（候選窗位置） | `ITfContextView::GetTextExt` 取游標位置 |
| 候選窗 `NSPanel` | 自己畫的頂層視窗（不搶焦點、`WS_EX_NOACTIVATE`）；全螢幕遊戲等情境可再實作 `ITfCandidateListUIElement`（UI-less 模式） |
| `activateServer`／`deactivateServer`／`commitComposition` | `ITfTextInputProcessorEx::Activate／Deactivate`、焦點變更（`ITfThreadMgrEventSink::OnSetFocus`）時送出組字區 |
| Info.plist 註冊 | COM 註冊（InprocServer32、ThreadingModel=Apartment），用 `ITfInputProcessorProfileMgr` 註冊繁體中文（LANGID 0x0404）的語言設定檔，用 `ITfCategoryMgr` 註冊 `GUID_TFCAT_TIP_KEYBOARD`；要支援 Microsoft Store／沉浸式應用程式與工作列語言列時，另需 `GUID_TFCAT_TIPCAP_IMMERSIVESUPPORT`、`GUID_TFCAT_TIPCAP_SYSTRAYSUPPORT` 等類別 |

特別注意：
- **32 位元與 64 位元**：32 位元應用程式會載入 32 位元的 TIP，所以通常要同時提供 x86 與 x64 的 DLL；ARM 版 Windows 則視需要提供 ARM64 版本。
- **DLL 會載入到每個應用程式裡**：
  - 模型檔用檔案對應（file mapping）讀取，各程序可共用同一份實體記憶體。
  - 引擎狀態每個程序各一份，這點和 Mac 版「單一輸入法程序」不同。
- **選字記憶的多程序寫入**：多個應用程式可能同時寫 `user-model.json`。
  - 寫入要「先寫暫存檔再取代」，並在寫入前重新讀檔合併，或用檔案鎖。
  - 也要能偵測檔案被其他程序更新後重新載入，否則 A 程式學到的，B 程式看不到。
- **AppContainer（沙盒）應用程式**：
  - Microsoft Store 類應用程式中，DLL 讀取的檔案（模型、記憶）必須允許 AppContainer 讀取。例如放在 Program Files 底下的安裝目錄，或設定 ACL 給「ALL APPLICATION PACKAGES」。
  - 這類程序通常也不能寫使用者資料夾，學習時要容錯，寫入失敗不能當掉。
- **密碼欄位**：不應該在密碼欄位進行組字。請確認 TSF 在密碼欄位的實際行為。

### 8.4 鍵盤對應（大千，依實體位置）

Mac 版用實體按鍵碼對應美式鍵盤字元（`KeyMapping.swift`）。Windows 可以用虛擬鍵碼（VK）對應同一組字元，引擎的 `DaChenLayout` 不用改：

| 字元 | VK | 字元 | VK |
|---|---|---|---|
| `a`–`z` | `'A'`–`'Z'` | `0`–`9` | `'0'`–`'9'` |
| `,` | VK_OEM_COMMA | `.` | VK_OEM_PERIOD |
| `/` | VK_OEM_2 | `;` | VK_OEM_1 |
| `'` | VK_OEM_7 | `-` | VK_OEM_MINUS |
| `=` | VK_OEM_PLUS | `[` `]` | VK_OEM_4 / VK_OEM_6 |
| `\` | VK_OEM_5 | `` ` `` | VK_OEM_3 |
| 數字鍵盤 | VK_NUMPAD0–9、VK_DECIMAL、VK_ADD、VK_SUBTRACT、VK_MULTIPLY、VK_DIVIDE | 其他 | VK_RETURN、VK_SPACE、VK_BACK、VK_DELETE、VK_ESCAPE、VK_TAB、方向鍵、VK_HOME/END、VK_PRIOR/NEXT |

- VK_OEM_* 會隨鍵盤配置變動。若要嚴格依實體位置，可以改用掃描碼（scan code）對應。
- **Ctrl／Alt／Win 組合鍵**一律交給應用程式，對應 Mac 版的 Command／Control／Option。
- Shift 與 Caps Lock 的狀態用 `GetKeyState` 判斷。

### 8.5 中英切換（需要跟使用者確認）

> **已決定（2026-11-20）**：Windows 版用 B，單按 Shift 切換，不提供 Caps Lock 模式；中英狀態所有程式共用。另外，組字中切換時組字區留著，不先送出（2026-11-23 使用者要求），和下面原本的建議不同。見第 6 節的 Windows 版決策。

macOS 有「Caps Lock 切換 ABC」的系統功能，所以 Mac 版不用處理。**Windows 沒有對應的系統功能，輸入法必須自己提供中英模式**。可選的做法：

| 做法 | 說明 |
|---|---|
| **A. Caps Lock 切換**（與 Mac 習慣一致） | Caps Lock 燈亮＝英文模式（輸出小寫，Shift+字母為大寫），燈滅＝注音。注意密碼欄位與其他輸入法下 Caps Lock 是真的大寫鎖定 |
| **B. 單按 Shift 切換**（微軟新注音的預設） | 只有「Shift 單獨按下、放開之間沒有其他鍵或滑鼠」才算切換，Caps Lock 維持一般功能 |

建議兩種都做成可選設定，預設值請詢問使用者。在 Mac 上的討論中，使用者習慣用 Caps Lock，但也知道微軟預設是 Shift。

切換到英文模式前，要先送出組字區。英文模式下按鍵直接交給應用程式，或輸出半形字元。

### 8.6 候選窗與顯示

> Windows 版後來改成比照 Windows 11 的微軟注音（2026-11-23 使用者要求）：15 號字、淺灰反白加強調色短線、右側圓點表示頁數。見第 6 節的 Windows 版決策。

- 直式清單，每頁 9 個，左側是 1–9 的編號，反白目前項目，右下角顯示頁碼。
- 跟隨系統深淺色，字型用 Microsoft JhengHei（微軟正黑體），約 20pt。
- 位置在游標那一行下方，放不下就放上方，不超出工作區。
- 不可以搶焦點。
- 組字區顯示整段底線，正在選的那段用粗底線（display attribute）。

### 8.7 在 Windows 上建模型

模型檔不在 git 裡，建置需要語料與 `bangbang-tool`。有三個選項：

1. **最簡單**：在 Mac 執行 `scripts/build-model.sh`，把 `build/bangbang-v3.lm` 複製到 Windows。
2. 用 **Swift for Windows** 編譯 `bangbang-tool`。注意 `Package.swift` 對它連結了 macOS 的 Carbon（只用於 `register` 指令），在 Windows 上要拿掉或條件編譯。
3. 把建模型的程式（`SourceDictionary`、`CorpusCounter`、`ModelBuilder`）也移植。語料下載見 `scripts/download-corpus.sh`。

不論哪種，**請用 `eval` 確認正確率與 5.1 一致**（99.4% / 82.8% / 82.1%）。

### 8.8 安裝與發布

- 安裝程式需要以系統管理員身分註冊 COM 與 TSF 設定檔（`regsvr32` 或安裝程式呼叫 `DllRegisterServer`），並把模型與 DLL 放到所有應用程式都能讀取的位置。
- 解除安裝時要取消註冊、移除檔案，並保留使用者的選字記憶（除非使用者要刪）。
- 未簽章的安裝程式會被 SmartScreen 警告；自用可以接受。
- 更新 DLL 時，已載入舊 DLL 的應用程式要重新啟動才會用新版。必要時提示使用者登出或重新開機。
- **Windows 版的做法**（2026-11-23）：
  - `windows\scripts\package.ps1` 做出安裝包，裡面的 `install.cmd`：
    - 把檔案裝到 `C:\Program Files\BangbangZhuyin` 並註冊 x64、x86（一次 UAC）。
    - 登錄到「已安裝的應用程式」，並加進鍵盤清單。
    - 更新時把使用中的舊檔改名，重新開機時刪除。
  - `uninstall.cmd`（或「已安裝的應用程式」的解除安裝）會保留選字記憶。
  - 細節見 `docs/WINDOWS_PLAN.md` 第 7 階段，使用說明在 `windows/package/README.txt`。
